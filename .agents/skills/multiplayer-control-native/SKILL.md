# 独立联机控制服务

同时读取工作区 [交付 Skill](../../../../.agents/skills/bugg-delivery/SKILL.md) 与 `E:/code/docs/Bugg交付清单.json`，遵守唯一的产品范围、C++ 运行边界及证据验收契约。下文兼容适配器是待迁移现状，不是保留 Python 产品运行方案的授权；不能用 C++ 中心已存在来宣称整个统一服务已原生化。

项目默认 `E:/code/buggcraft-control-native`。开工读根 AGENTS、docs/00-规划总览.md、06-复用与方法DOM清单.md、07-生命周期与一致性.md。当前 0.1 已有服务和隔离验收，部署目标已改为上海 node.bugg.icu；补读 docs/08 的接口、09 的实测缺口和 10 的历史部署，当前状态查交付清单及新证据，不把旧北京记录、原型、合成目录、CI 或单节点上线写成当前全网迁移完成。玩家登录只在控制主机；受管节点拒绝旧账号/directory 登录，设备委托必须由控制主机先授权，管理员凭据不得下发到节点。

按职责读取唯一契约：系统和信任边界见 01，长期接入/账号/消息协议见 02，地区/容量/房间归属见 03，ISA 和验收见 04，实施和旧系统迁移见 05。不在 Skill 复制接口清单或阈值。修改契约同步入口和相关调用方。清单命令为 `python scripts/inventory.py`、`--check`，文档门禁为 `python scripts/check_docs.py`。

当前网页和节点删减清单维护在相邻节点项目 `docs/13-服务精简与复用验收.md`，部署见本项目 10。控制与节点独立、可同机部署；第三方控制使用同一入网协议和可配置的 origin/CA/公钥。网页不再承载联邦备份或游戏社交，节点不带前端或管理员入口。复用现有账号/设备适配器，不在本项目复制 Vue、加密身份或 SSH 转发。

先检索清单、源码、调用方与依赖库，扩展唯一所有者。控制中心、节点、桥、SDK、启动器不得各写一套分配/认证规则。跨仓源码复用先核实授权，现有 Python 原型仅供协议行为研究；优先复用已有传输和成熟库，不以独立闭源项目为由直接复制 AGPL 实现。机器方法/DOM 索引只登记真实源码，计划与已实现分开。

长期接入凭证允许复用但只授予注册能力，默认无到期时间且可撤销轮换。安装包中的公开凭证不能当作安全秘密或信誉。每节点独立密钥、可撤销身份与最小权限，第三方节点不获得全网主密钥。注册自动化和可接纳玩家资格由不同状态管理，避免给每台新机器额外引入人工批准。

分配复用 Placement：先硬过滤，再小量实测探测与按容量加权分散，原子预留后才返回签名票据。保持房间归属和会话黏性；候选失败须有界重试，不能全量探测、自动跨区全网扩散或将所有客户端指向单一最低 RTT 节点。

性能采用 Release 和库的运行时分派，保留通用实现与关闭路径；不手写密码算法或全局要求 AVX。按 04 的多轮负载、错误、P99、资源和故障矩阵出报告，不把旧原型或 JSON 微基准结果冒充新控制服务或游戏性能。

开发验证遵守 07 的持久确认、幂等、租期、多设备、取消及资源所有权。使用独立本地或授权服务器环境；原始证据写 validation-artifacts，正式结论写编号 docs。按用户授权推进可逆工作，不自行增加审批环节。

诊断构建的资源约束见根 AGENTS 与 docs/09；共享 4 GiB 服务器不再运行 sanitizer/Debug 重型构建。`scripts/limited_build.py` 仅提供单进程内存和本次进程组超时清理，不把它当作整棵进程树的 cgroup 总内存上限。
