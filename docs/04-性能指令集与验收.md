# 性能、指令集与验收

0.1 已有隔离环境实测，见 [09-开发验收与性能报告](09-开发验收与性能报告.md)。下述规模仍是测试设计和分阶段目标，不是已达到的容量。控制服务优化的是注册、在线、事件和调度；游戏转发速度仍需用现有节点/桥的真实数据面单独验证。

## 实现策略

C++20 Release、合理 LTO 和符号包；基线二进制保留目标架构最低要求。异步 I/O、区域索引、少量候选、批量读写、持久连接、只读快照和有界队列优先。数据库调用、磁盘日志、DNS 和证书更新不得同步阻塞网络事件循环；限并发、设超时，避免为了吞吐制造无界内存。

JSON 批解析可评估 simdjson 的运行时分派；哈希/签名/TLS 复用 OpenSSL 的硬件实现；大批健康评分只有在剖析确认算术占比明显时才做 SIMD。签名、权限、数据库事务和分配语义不因 SIMD 改变。禁止通过关闭认证、丢事件、跳过确认或放宽容量约束获得“提速”。

不全局指定 `-march=native`、`/arch:AVX2` 或 AVX512。库/独立内核检查 CPU 和操作系统寄存器状态后选择实现，保留通用路径及进程级关闭选项；AVX512 是否启用以本机 P99 和吞吐结果决定。simdjson 明确要求保留最低编译基线，避免破坏其运行时分派。[官方运行时分派说明](https://github.com/simdjson/simdjson/blob/master/HACKING.md)

## 平台与架构

| 范围 | 计划验收 |
| --- | --- |
| Linux x86-64、ARM64 | 首批正式控制服务构建与实机测试 |
| Windows x86-64、ARM64 | 控制服务/部署工具兼容验证，实机缺口单列 |
| macOS ARM64、x86-64 | 开发与客户端适配构建，真实硬件性能独立记录 |
| 其他编译器/库支持的架构 | 先验证通用回退、编译/模拟器正确性，再按真实需求提供发布目标 |

可评估 x86 SSE/AVX2/AVX512、ARM NEON 与库支持的其他后端；不能把“其他架构可以走通用实现”写成“所有架构所有 SIMD 都已优化”。x86-64 基线本身已有 SSE2，“不用指令集”在报告中具体指关闭可选 ISA 内核，不承诺生成完全不含基础 SIMD 的系统/标准库。

## 对照矩阵

1. 同版同输入：通用 JSON/评分后端与自动 ISA，保持密码算法和存储配置一致。
2. 同版同密码算法：OpenSSL 正常硬件路径与受控关闭相应硬件路径，注明支持的掩码和库版本，不能顺便换算法。
3. 旧实现/新实现：单独比较索引、批处理和调度算法，不能归因于 ISA。
4. 最终系统：TLS、真实持久化、容量预留、消息确认和故障恢复均开启；微基准与端到端分别报告。

每组同机同编译版本、同核数与功耗设置，预热后至少 5 轮，交错运行顺序；同时保留中位数、范围、P50/P95/P99、错误率、CPU、RSS、网络、数据库/队列等待和正确性。压测客户端尽可能独立机器，记录自身瓶颈，不能把本机回环上限当公网成绩。

## 负载与稳定性矩阵

| 阶段 | 工作负载目标 | 要点 |
| --- | --- | --- |
| 小规模正确性 | 100 节点、1,000 玩家会话 | 重复注册/邀请、原子预留、跨地区加入、撤销和重启恢复 |
| 中规模 | 1,000 节点、10,000 玩家会话 | 长连接、抖动心跳、突发登录、好友事件与选择延迟 |
| 大规模 | 10,000 节点、100,000 玩家会话 | 分区索引、候选有界、集中启动、区域热点与内存增长 |
| 故障负载 | 单实例退出、数据库切换、缓存丢失、区域隔离、证书轮换 | 已确认事件与配额不丢/不超卖，重连无蜂拥，已有游戏载荷继续 |

采用上述建议心跳间隔时，10,000 节点约有 2,000 次/秒节点心跳；100,000 玩家约有 10,000 次/秒玩家心跳，尚未包含注册、邀请、探测及重试。生成器需按这些来源分别统计，不能将合并后的批次数当作玩家事件数。

局部自动验收：百请求抢一个槽只能成功一次；同幂等键只有一次业务效果；旧 epoch 不复活；候选/探测数不随总节点数增长；节点不获得其他玩家社交资料；控制服务退出后既有游戏载荷、哈希与 EOF 正确。指标目标先在 M1 基线后形成门槛，避免用未经测量的“百万 QPS”“8 倍”规划容量。

## 报告产物

原始数据、命令、源码/构建摘要、依赖与 CPU 信息写 `validation-artifacts/`；正式结论写编号性能报告目录，并由总览链接。区分直接公网、LAN、回环、SSH 隧道、模拟器和真实硬件。没有 macOS/ARM 实机时明确未测。

兼容功能通过不等于压测通过，Python 原型的 96/51 项测试也不能成为本 C++ 服务的性能结果。ISA 上线以真实端到端收益且 P99/错误/正确性不退化为门槛；无收益则保留库分派和基线，不为存在 Intrinsic 而增加维护成本。
