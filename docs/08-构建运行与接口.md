# 0.1 构建、运行与实际接口

2026-11-11 房间目录新增接口仍归 Placement：`room/publish` 接收 room_id、reservation_id、room_epoch、secret 和节点确认的 room 描述，仅同一房主设备可写；`room/list` 接收可选 query，返回明确 public/require_invite、名称、版本、加载器和世界状态，不含秘密；`room/resolve` 按 room_id 校验有效房主和加入策略，仅返回解析结果，不分配槽位。`placement/reserve` 的 join 可携带已有邀请 secret，中心核对 room_id 摘要后继续原节点分配。错误区分 not_found、unpublished、invitation_required、node_unavailable；旧 locate/inspect 保持原用途。详见 [13](13-大厅房间目录修正.md)。

本篇描述已实现的独立 C++ 服务。源码唯一所有者：`service.cpp` 负责鉴权/事务入口，`enrollment.cpp` 负责身份/节点，`placement.cpp` 负责候选/配额/房间，`social.cpp` 负责设备在线与持久事件，`server.cpp` 只适配 HTTPS/WSS 和有界工作池。没有复制相邻 AGPL 项目的业务代码。

## 构建与依赖

需要 C++20、CMake ≥3.25、Boost ≥1.74、OpenSSL ≥3、PostgreSQL libpq ≥14、simdjson、nlohmann/json。实际 Linux 验收版本见根 `dependencies.lock.json`；Windows/macOS 的 vcpkg 使用清单里的固定 baseline。根 `THIRD_PARTY_NOTICES.md` 记录第三方许可来源。

Ubuntu 24.04 示例：

```sh
sudo apt-get install build-essential cmake ninja-build libboost-dev libssl-dev libpq-dev libsimdjson-dev nlohmann-json3-dev postgresql
cmake --preset release
cmake --build --preset release --parallel 1
ctest --preset release
python -m pip install -r requirements-dev.txt
python scripts/inventory.py --check
python scripts/check_docs.py
CONTROL_BINARY="$PWD/build/release/buggcraft-control" python tests/integration.py
CONTROL_BINARY="$PWD/build/release/buggcraft-control" CONTROL_JSON_BACKEND=fallback python tests/integration.py
```

测试自行启动独立 PostgreSQL、TLS 服务与协议节点夹具，测试结束后关闭。`initdb` 要求普通用户，不使用生产数据库。Windows 没有本机 PostgreSQL 时可由测试协调器提供独立测试库的 `CONTROL_TEST_DATABASE`；它不是生产连接串输入。Windows 实测通过 SSH 到隔离库，见 09。

共享 4 GiB 服务器不运行 sanitizer/Debug 重型编译。诊断构建转到独立开发机/虚拟机；Linux 可用 `python scripts/limited_build.py --memory-mib 1024 --reserve-mib 768 --seconds 300 -- cmake --build build/diagnostic --parallel 1`。该脚本检查启动前可用内存、限制每进程地址空间/CPU、总时长并清理本次进程组；不是 cgroup 总内存隔离。预算不足或触限停止，不自动调高上限。资源限制验证命令为 `python tests/limited_build.py`，恢复和实测状态见 09。

Windows/MSVC、macOS 的标准依赖入口为根 `vcpkg.json`：

```sh
cmake -S . -B build/portable -DCMAKE_TOOLCHAIN_FILE=/path/to/vcpkg/scripts/buildsystems/vcpkg.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build/portable --config Release --parallel 2
ctest --test-dir build/portable --build-config Release --output-on-failure
```

CI 定义了 Linux 构建/集成/通用后端检查、Windows x64 和 macOS ARM64/x64 编译单元检查。macOS 使用 15 的显式架构入口，按 [GitHub 官方 runner 清单](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) 维护。配置 CI 不等于已在远程平台运行通过。Dockerfile 使用发行版自身的一套 PostgreSQL/libpq 包；本轮本机 Docker 构建遭遇源下载及 PGDG/发行版版本冲突，最终修订镜像配方后未作为已验收交付，优先使用已实测的 CMake 路径。

## 配置和启动

复制 [config.example.json](../config.example.json) 为部署配置。私钥、管理员凭据和数据库连接串分别存文件；Unix 权限必须不授予 group/others（例如 0600），Windows 使用仅服务账号可读的 ACL。配置文件相对路径基于该配置所在目录解析，不依赖启动工作目录。TLS 默认启用，最低 TLS 1.2；没有 HTTP 明文模式。

```sh
umask 077
mkdir -p secrets
openssl genpkey -algorithm ED25519 -out secrets/signing-ed25519.pem
openssl rand -hex 32 > secrets/admin-token
# secrets/database.conninfo 由部署工具写入，例如本机 Unix socket、数据库、服务用户和 connect_timeout。
# 使用真实域名证书写入 secrets/tls-chain.pem、secrets/tls-key.pem。
./build/release/buggcraft-control --config config.json
```

服务默认监听回环地址；部署后按真实反向代理/TLS 方案选择监听地址，不自动开放公网、防火墙或替换现有节点。systemd 模板位于 `packaging/buggcraft-control.service`，没有执行安装。

重要配置：

| 配置 | 当前语义 |
| --- | --- |
| `io_threads/workers/queue_limit/max_connections` | 网络线程、数据库工作线程、有界任务/连接预算；库连接不在网络线程同步等待 |
| `json_implementation` | `auto` 为库检测 CPU/OS，`fallback` 为禁用可选 JSON SIMD；其他名称仅本机运行时支持时接受 |
| `allowed_pools` | 候选和最终预留的服务端信任池限制；示例默认 `official`，社区注册不会自动变成官方 |
| `region_routes` | 服务端允许的相邻地区；客户端 `nearby` 只能提示其中至多三个，不能自己授权全网跨区 |
| `node_slot_limit/node_bandwidth_limit` | 每节点自报资源的中心上限，不等于已经实测其真实出口能力 |
| `allow_loopback_nodes` | 仅独立测试需要 true；正式配置 false，探测拒绝私网、映射地址、链路本地、回环和组播 |
| 租期与运行授权 | 心跳/预留租期可配；节点/玩家运行授权默认 900 秒，长期入网凭证没有自动到期 |

0.1 使用固定数量工作线程及每线程复用的 libpq 连接，语句 5 秒、锁等待 2 秒、连接 3 秒超时；不是 libpq 全异步实现。控制请求需要数据库成功，不伪造缓存命中成功。两 API 实例可共享数据库/签名密钥，数据库主备和负载均衡仍由部署层落实。

## HTTP/WSS 规则

HTTP 操作均为 `POST /v1/...`，JSON 对象，最多 64 KiB、嵌套 24 层；拒绝重复 JSON 键。鉴权使用 `Authorization: Bearer ...`，管理员令牌独立。响应失败为 `{"error":{"code":"capacity","message":"..."}}` 并带对应 4xx/5xx；临时忙/限流带 Retry-After。无凭据/私钥/数据库 SQL 进入响应和日志。

`GET /v1/channel` 只用于有有效节点/玩家身份的 WSS 升级。每消息为 `{"request_id":"...","path":"/v1/...","body":{...}}`，响应带 request_id/status/body。WSS 和 HTTP 调用同一个 Service/域方法，不复制规则。节点可用该长连接发心跳/确认；玩家 `social/subscribe` 携带 `after` 订阅事件，当前每秒按数据库游标增量推送。输出队列最多八帧，读写串行，慢端关闭后可凭游标重放；不会把管理员令牌放查询串。

订阅的读取进度不等于 delivered：设备必须明确 ACK。现阶段推送是有界轮询，不宣称十万真实连接已通过。

## 身份与长期接入

管理员用 `scripts/admin.py`：令牌文件、正文文件、可选 CA 文件，强制 HTTPS 并校验证书。正文中的长期入网凭证也是敏感文件，不加入仓库或命令行。

| 路径后缀 | 请求／结果 |
| --- | --- |
| `health` | 版本、实际 JSON 后端、中心签名公钥、OpenSSL 实际 CPU 设置；不返回任何私钥 |
| `admin/credential` | `id,credential,pool,quota?` → 长期可复用凭证摘要；同 ID 轮换，默认 expires_at=null |
| `admin/credential/revoke` | `id` → 停止新注册，已注册节点身份独立 |
| `admin/node` | `id,status`，状态仅 probing/draining/revoked，不允许管理员直接伪造探测通过 |
| `admin/device/revoke` | `account_id,device_id` → 撤销设备运行授权 |
| `enrollment/challenge` | Ed25519 `public_key` 小写十六进制、长期 `credential`、protocol=1、region/operator、numeric-IP:port 入口、slots/bandwidth → 60 秒挑战和精确待签字符串 |
| `enrollment/prove` | `challenge_id,signature`，节点对字符串 UTF-8 原文签名，签名十六进制 → 独立 node_id、epoch、运行授权；不发送主密钥 |
| `node/activate` | 节点运行授权 + `proof_endpoint` → 实际游戏 TCP 可达，且同 IP 的 TLS proof 入口对中心新 nonce 作节点密钥签名，之后 active |
| `node/heartbeat` | `sequence,observed_slots,observed_bandwidth` → 服务端租期；倒序/重复不续租 |
| `node/renew` | 有效节点身份 → 更新短期运行授权；失去授权后可用独立节点私钥重新挑战 |

恢复节点身份时，challenge 用 `node_id` 代替 credential；中心核对原公钥，prove 仍需原私钥。长期凭证撤销不使这条恢复路径失效，节点独立撤销则所有路径拒绝。重复 prove 返回原 epoch；旧挑战被后续证明取代后拒绝重放。0.1 同身份新证明替换旧 epoch，但未建立跨实例的“同一 token 仅允许一条物理通道”租约，不能把磁盘复制检测写成全面完成。

proof 入口：`POST /.well-known/buggcraft-node-proof` 收到 `nonce,endpoint`，返回 `signature`，签名原文 `buggcraft-node-proof-v1\n{nonce}\n{endpoint}`。中心在验证节点私钥新签名后信任结果，probe TLS 证书本身不作为节点信任来源；普通客户端至中心 TLS 始终验证证书。该端点尚未接入现有生产节点，夹具实现仅用于验收；游戏端口可达不证明游戏握手/出口带宽已验收。

## 玩家、社交和分配

新测试身份可用 Ed25519 公钥 + device_id 走 identity/challenge、identity/prove。既有账号提交公开 certificate、issuer_signature、device_id：中心独立验证 SSH Ed25519 发行签名、原完整账号 ID，再验证用户 P-256 私钥对新挑战的证明。P-256 JWK 与 Base64URL 64 字节 r||s 编码兼容现有账号，不按用户名合并，不读取密码、用户私钥或保险箱。`identity/lookup` 需要玩家授权，identifier 为完整 ID 或用户名，最多返回八个候选。

| 路径后缀 | 核心字段与约束 |
| --- | --- |
| `presence/open` | idempotency_key → 服务端 session_id；每账号最多 32 活会话、16 设备 |
| `presence/refresh`、`presence/close` | session_id、sequence；旧 epoch/倒序/已关闭不复活 |
| `presence/view` | account_id，仅自己或已接受好友；online/offline/unknown 与有效会话数 |
| `social/apply` | event_id、target、kind、必要 room_id/room_epoch；同 ID 同内容幂等，不同内容 conflict |
| `social/inbox`、`social/subscribe` | after 游标，64 条/批；后者只用于 WSS；数据库 Outbox 与事件同事务 |
| `social/ack` | cursor 或 cursors（1–64 个正整数）、state=delivered/seen；整批仅收件人设备可确认，重复游标幂等 |
| `social/state` | 当前账号、好友、在线三态、申请/邀请与 outgoing deliveries；桥/SDK 共用快照，持久确认不等于已读 |
| `placement/candidates` | region、operator、nearby?；区域/池/健康/分桶索引，最多八候选，返回 30 秒 probe_token，探测并发建议三 |
| `placement/reserve` | idempotency_key、intent=new/join/recover、room_id、slots、bandwidth；新建/恢复附 probe_token 与 measurements；原子预算复核，账号最多八个活分配 |
| `placement/confirm` | 节点授权、reservation_id、完整 ticket；仅所属节点确认/续租，活分配 120 秒，建议每 30 秒续租 |
| `placement/refresh` | 节点授权、reservations（1–256 条 reservation_id、可选布尔 release）；只续租已确认且未过期的本节点分配，或释放；逐项返回 state/error，不接受新入场，不需再次传送玩家票据 |
| `placement/release` | reservation_id；所属玩家/节点可释放，重复幂等，不作用于新一代房间 |
| `placement/reconnect` | reservation_id；同账号同设备且预留有效时换发短期票据，不换节点、不增加槽位 |
| `room/list`、`room/inspect` | list 返回本人/被邀请可见房间；inspect 仅好友可查申请所需 epoch，不授予加入权限 |
| `room/locate` | room_id；所有者/有有效邀请或加入许可者可读取，返回固定 node/公钥/epoch |

事件 kind：friend_request/accept/reject、invite/revoke、join_request/accept/reject。邀请/加入许可约 300 秒，加入申请 120 秒，好友事件七天；关系长期保存。过期事件七天后按批清理，审计 30 天。消息最终发布按提交顺序串行，避免序列游标提交乱序漏读；这也是后续需实测的社交吞吐约束。

分配签名格式为 `hex(JSON_UTF8).Ed25519_signature_hex`，声明中有独立用途 audience、玩家/设备、node/固定公钥/入口、room/epoch、reservation、资源与期限；不能把它当作原 SSH 接入码。候选质量窗口当前最佳 RTT +20 ms，窗口内容量加权 Rendezvous，先预留后确认。跨区好友加入只查询原 room owner，不重新选“最近节点”。客户端 RTT/节点自报负载只是提示，最终中心账本原子限制。

## 本版边界

北京节点、原生桥/SDK 和启动器已接入统一控制登录，实际部署和直接公网载荷验证见 [10](10-IP部署与受管接入.md)。其他地区旧节点未自动迁移，单节点成功不等于全网验收。

控制主机账号适配器用 admin/device/authorize 提交 certificate、issuer_signature、device_id、device_grant、delegation_signature、expires_at。crypto::verify_delegation 统一校验原账号公钥绑定、原用户签名和设备 JWK；授权不超过浏览器设备租期，refresh 不复活已撤销设备。admin/device/revoke 同步撤销中心身份，未授权委托不能直接完成 identity/challenge。节点不持有管理员文件。placement/confirm 附 admission=true 时重新检查设备撤销与有效期。social/apply 另支持 friend_remove；桥读取 inbox 后批量 ACK delivered，不自动提交 seen。

0.1 已有服务端池限制、相邻地区白名单、draining 和健康租期；GeoIP/ASN 可信数据源、带宽自动测量、软过载滞回/余量模型、区域重连令牌桶、签名分发清单、生产证书热更新、密钥多版本轮换、旧好友签名迁移和数据库故障仲裁尚未完成。API 副本通过不等于数据库高可用。相关发布门槛仍按 05 执行。
