# 大厅房间目录修正

2026-11-11，范围是截图中“junsizz / 公开·自由加入 / 准备中”却提示需要邀请的房间。没有进入或关闭真人房间，没有启动 Minecraft。

## 根因与线上诊断

上海只读查询发现，该记录房主的 active reservation 持续续期，节点也在线，不能按过期僵尸房间处理。旧 `/v1/room/list` 返回的是本人或收到邀请的容量预留，只包含账号名、room id、epoch、unknown；未包含真实房间名称、公开方式与游戏信息。QML 把缺失的 require_invite 当 false，unknown 当准备中。与此同时，桥 `ControlClient::resolve` 只遍历社交邀请，公开加入及本人解析都没有实现。

这次没有删玩家数据或伪造房间状态，也没有把网络失败统一解释为需要邀请。

## 唯一所有者与实现

- 控制服务原 Placement 统一负责发布、列表、解析和加入权限。`rooms.listing/secret` 是追加字段；未发布描述不进入大厅。列表仅选公开房间、已确认且有效的房主 reservation、有效节点健康租期，并支持原搜索条件；不返回邀请秘密。
- `room/publish` 检查当前房主 reservation、设备、epoch、秘密摘要和明确策略；`room/resolve` 仅解析，不分配、不加入。公开自由加入可解析；需邀请只允许房主或有效邀请用户。复制邀请作为能力支持原加入流程，节点继续验证秘密和分配票据。
- 桥和 C ABI SDK 复用 ControlClient/Rpc/Session。现有 describe 轮询同步真实描述，相同描述不重复写库，失败下次重试。仅发布版本、加载器、连接数、容量、公开策略等有界字段，不上传模组清单。
- 启动器复用 MultiplayerService/NativeBridge，区分失效、邀请和节点不可达，网络失败保留列表。未知策略显示“房间信息未同步 / 状态未知”并禁止加入，不再显示“自由加入”。确认失效的单条记录才立即移除。QML 只组合现有组件。

沿用原工作线程、取消代次和定时器；无新增网络轮询、线程或游戏进程。没有主张整体性能提升。

## 实测

Linux x86_64 / WSL Ubuntu 24.04，Release：控制单元测试通过；22 项隔离 PostgreSQL/TLS/WSS 集成通过，包括未确认/未发布/已过期房主不展示，正确名称与版本、搜索、公开解析、邀请拦截、复制邀请和关闭后不可解析。11 项账号回归通过，覆盖授权、刷新撤销、邮箱与找回。

Windows 11，MSVC 控制服务 + MinGW 原生桥/核心 + 隔离 Docker PostgreSQL：四项实际集成通过，分别为 CLI 和 SDK 的公开目录/无社交邀请加入/复制邀请/关闭，以及原邀请/断线重连/中心停止后已有载荷继续传输。使用回声 TCP 载荷和 EOF 校验，没有打开 Minecraft。证据为 `validation-artifacts/room-directory-windows.json` 与对应四份日志。此次未重测 macOS/ARM 或公网游戏。

Qt 6.8.1 / MSVC：RuntimeTest 的连接错误提示和原房间事件/空轮询检查共 5 项计数（含初始化、清理）通过，无跳过；原生运行依赖和 QML 组件边界两项 CTest 通过。两个 UI 测试通过；qmlformat/qmllint 完成，本次 RoomsPage 无新警告，已有 BuggLoginPage 登录信号参数警告未在本次修改。
