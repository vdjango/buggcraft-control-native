# 北京 IP 部署与受管接入

2026-11-10 用户授权北京 `81.70.85.232`（2 核/4 GiB/70 GB，6 Mbps、600 GB/月）部署替换，已完成。启动器登录地址为 **https://81.70.85.232**，指向控制入口；玩家不再登录转发节点。构建在本地 Windows/Ubuntu 开发环境完成，没有在该 4 GiB 服务器重型编译。

统一入口的 /v1/ 交给独立 C++ 控制服务；/api/launcher/ 与浏览器账号授权由精简身份适配器承担，旧恢复文件与联邦备份已删除。启动器使用控制主机 HTTPS origin 完成设备授权，以用户签名委托和设备私钥挑战换取中心身份；不发送用户私钥和保险箱，撤销同步失效。

账号模块仅在控制主机运行，不监听游戏端口。C++ 控制、身份适配和转发节点为三个独立进程。后续精简已移除节点管理员与玩家网页/前端资产，旧 HTTP 登录/注册/授权/管理返回 404，SSH 旧账号、共享密钥和 directory 被拒。删减与复用唯一清单见[服务精简报告](../../minecraft-tunnel-native/docs/13-服务精简与复用验收.md)。

节点适配归开源节点项目，负责独立入网、心跳、proof 端点、分配验票、入场确认、续租与释放；游戏字节留在原生核心。桥和 C ABI 共用 Rpc，读取受管元数据后调用中心的候选/预留，加入已有房间固定 owner；启动器不复制调度规则。旧联邦与受管流量不能无预算混用。

IP 测试证书必须包含 IP SAN；客户端只信任该部署交付的证书/CA，不忽略所有 TLS 错误。控制服务仅回环监听，由现有 443 入口分路，数据库不开放公网。替换前保留配置、可执行文件和账号数据备份，验证服务与外网请求后才切换。

## 证书、回退和未覆盖项

IP采用含81.70.85.232 SAN的部署测试证书。启动器仅对精确IP请求提供嵌入公开证书；桥/节点配置同一信任锚。Windows Schannel 对该自签名叶证书仍报不受信，HttpClient 只确认与请求 PEM 完全一致的证书及 SelfSignedCertificate 错误；其他错误、过期和主机不符仍拒绝，不改变系统 CA。实现按 [Qt 精确证书错误确认接口](https://doc.qt.io/qt-6/qsslsocket.html#ignoreSslErrors-1)，没有调用无参数的全部忽略。浏览器尚未信任测试证书时会提示；公开发布应改为域名与受信证书。

首次切换因启动前 host_key 是路径而非对象失败，自动回退旧节点；修复为复用 Federation 已加载密钥，并增加相同生产形态回归后，于18:14成功切换。18:35仅升级控制二进制，保留节点游戏进程。原始失败与最终验证均保留于 validation-artifacts，不隐去失败。

Qt最终公网测试曾发现 Schannel 不接受原先仅 setCaCertificates 的自签名叶证书，修复为上述精确证书/错误确认，随后13项全部通过。运行中的启动器占用输出文件导致一次链接失败；原可执行文件改名保留、旧进程继续运行，18:48重新生成同一 build/bugg.exe，没有关闭用户窗口。源码、索引和文档门禁最终通过；临时数据库已停止。新控制链路的功能测试不替代此前ISA多轮性能报告。

旧服务/状态/配置备份为 `/var/backups/buggcraft-control-20261110-181431`（仅root可读），previous-release记录原版本。回退时先停止受管节点/身份适配，恢复该备份的server.conf、node-state.json及nginx.conf，移除node的control-native.conf drop-in、将节点current切回previous-release，再daemon-reload、nginx -t并重启原节点/重载Nginx。会中断该节点会话；不得把旧联邦和受管分配混用。控制二进制可独立切回183501之前的181431/control，保留数据库与签名密钥；数据库结构迁移为增加设备租期字段，不删原表。

其他地区旧节点本轮未迁移；大规模长连接、跨地区线路、真实GeoIP/ASN源、数据库主备、控制主机失效自动切换、macOS/ARM实机、AVX512和证书轮换仍未完成验收。旧账号/好友历史的全网迁移需要另行落实，不能因北京上线就宣布所有架构或全部节点已完成。
