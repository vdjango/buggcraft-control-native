# 生命周期与一致性

2026-11-11 房间目录：容量预留不是公开房间条目。只有当前房主分配已由节点确认且发布了真实房间描述，才进入公开大厅；列表、解析和加入统一检查 host reservation、epoch、节点健康与公开/邀请策略。未知描述不得推断为自由加入。`room/publish` 仅持有当前房主 reservation 的同一设备可更新，且邀请秘密须与 room_id 摘要一致；秘密不出现在列表。`room/resolve` 不分配槽位、不加入房间，只向符合策略的玩家返回秘密。已有复制邀请可作为加入能力；丢失房主或过期分配不可用。桥复用已有 describe 轮询同步描述，仅值变化写入，无新轮询器；发布失败保留会话，下次 describe 重试。未发布的旧分配不冒充公开房间，不删除玩家数据。

以下约束为系统资源和故障契约。0.1 的实际实现与未完成项见 08、09；不能删除这些语义来换取吞吐。

| 资源 | 所有者与并发 | 终止/失败 |
| --- | --- | --- |
| ServiceRuntime / io_context | 进程级运行期，管理 I/O 线程和工作池 | 停接新请求→排空/取消任务→关闭存储/网络→退出；SDK 不重复初始化同一运行期 |
| 节点 WSS/TLS 通道 | 每通道有一个 strand；身份和 epoch 绑定 | 对象销毁前取消计时器；回调用弱引用/代次检查，旧通道不能撤销新通道的租期 |
| 账号设备会话 | 按 account/设备分片唯一所有者 | 一个设备退出只关闭自己的会话；服务端租期失效 unknown，显式退出按最新 epoch 处理 |
| 注册/关系/撤销事务 | 域服务提交，Storage 执行有界事务 | 成功持久化才返回 accepted；提交结果不明通过幂等键查结果，不盲目重放另一个新操作 |
| Outbox/投递任务 | 每分片有界批任务，数据库为真相 | 设备确认后更新游标；重复消费幂等，TTL 到期停止；取消不丢已持久事件 |
| 候选快照 | Placement 发布不可变只读版本 | 过期或策略变更失效；快照不是配额账本，不阻止最终事务复核 |
| 预留/活跃分配 | Storage 原子账本，Placement 是唯一调用域 | 有期限与用途，确认/释放幂等；重复释放不减负数，旧代次不释放新分配 |
| 房间 owner/epoch | RoomDirectory + 容量事务协调 | 单一有效 owner，恢复增加 epoch；分区不随意另选节点制造双归属 |
| 数据库/缓存连接 | 有界池，I/O 线程不阻塞等待磁盘 | 设截止时间和退避；池满真实返回繁忙，不能无限创建连接 |
| 日志、指标与采样 | 异步有界队列 | 不记录私钥/令牌/账号密文/游戏载荷；写盘失败和丢弃有可见计数 |

租期在本进程定时使用单调时钟；跨实例使用存储或服务端可比较时间，客户端钟差不能改变配额和授权。证书和长期凭证撤销按策略版本/epoch 传播，缓存有失效窗口；不能在旧缓存中无限续期。

关系和事件持久确认、唯一房间 owner、容量确认属于强约束；在线和健康可短暂陈旧，但必须标注 unknown/数据年龄。部分区域不可达返回 partial 和范围，不把部分结果称作全网完整列表。

中心断连时数据面按既有授权/会话继续运行；新分配必须取得有效容量承诺，不能在没有权威配额时无限离线接纳。恢复采用有界随机重连，不让十万客户端在同一秒重试。TLS 建连、签名计算和数据库都纳入排队预算，而不是只限制最终 socket 数。

方法实现前写明输入、返回、业务/临时错误、线程、所有者、取消以及晚到结果处理；同一语义只由一个域方法执行。异步完成不等于持久完成，同步密码计算也不能伪称随时可取消。

0.1 运行期：HttpSession/WebSocket 持有 ConnectionLease，strand 上同一读/同一写不重叠；WSS 输出队列有界，轮询计时器回调为 weak_ptr。State 拥有固定工作池，线程独立拥有 libpq 连接；停机先停止/等待工作池并销毁排队任务引用，之后销毁 io_context 中的网络回调，最后销毁 State，避免析构跨过已结束的运行期。

配额更新锁节点行；尝试失败候选通过 savepoint 释放行锁，避免不同候选顺序形成锁环。账号/房间的 advisory 锁覆盖不存在记录时的并发；社交最终 cursor 发布到事务提交间串行，防止较大序号先提交导致客户端跳过较小序号。清理任务每分钟有限批量，不把历史累计记录一次全部加载进内存；保留期见 08。
