# 接入、账号与消息协议

本篇为目标契约；0.1 实际接口、编码和限制见 [08-构建运行与接口](08-构建运行与接口.md)，不把所有规划接口视作已发布能力。协议使用版本号、请求 ID、结构化错误、重试提示和大小限额；上线前冻结公开 Schema。控制传输为 HTTPS/WSS，节点注册后使用独立身份认证。节点侧适配继续归开源节点/桥项目。

## 长期入网与自动部署

长期凭证默认 `expires_at=null`，可供多台节点反复注册；不采用 Python 原型的“600 秒、绑定一台即消耗”规则。凭证由控制端生成足够随机的令牌，服务器仅存校验摘要，密钥与管理员配置分离；支持禁用、轮换、限流、所属节点池及可选总配额。旧新凭证可配置短暂交叠，轮换不要求重装所有已接入节点。

| 阶段 | 行为与持久结果 |
| --- | --- |
| 首次安装 | 官方分发清单提供可信 HTTPS 引导入口、协议版本及公开接入标识；私有节点池可配置自己的长期凭证文件 |
| 申请接入 | 节点本地生成独立私钥，提交公开密钥、随机数、软件版本、入口声明及长期凭证；不上传私钥 |
| 所有权证明 | 服务端挑战绑定控制服务 audience、节点公钥、随机数和规范化请求摘要；私钥签名后原子创建 node_id |
| 重试 | 同一公钥和幂等请求恢复原 node_id，不能重复创建成员或继承另一个节点身份 |
| 独立身份 | 返回可更新的节点证书/短期运行授权及本节点配置；日常连接不用长期入网凭证，也不持有全网共享主密钥 |
| 自动验证 | 版本、TLS/证书持有、公网入口、心跳和容量检测通过后，自动由 enrolled/probing 进入 active；失败时保留诊断和退避 |
| 重启/升级 | 使用已保存的独立身份恢复，重新上报入口与能力；版本不兼容暂停分配，已有流按策略排空 |

公开安装包中的令牌必须按公开信息设计：它能授予受限注册通道，不能作为“官方节点”身份或管理员权限。长期凭证撤销默认只停止新的注册；已接入节点由独立的节点撤销/隔离操作控制。私钥遗失需重新登记，旧身份撤销；复制持久目录到多台机器时拒绝并发冒用同一身份，而不是把多台算成一个节点。

平台私有服务的真实域名、证书及签名公钥尚未指定。发布前将它们写入可验证的分发清单；不把当前旧节点地址误当作已上线的 C++ 控制服务。不在仓库、CLI 参数、日志中放生产凭证；本地文件使用相应系统权限保护。

## 账号与认证迁移

控制端统一 account_id 的公开目录、设备授权和在线会话路由。旧完整账号 ID、公钥、好友关系及用户证明继续有效，不能按重名自动合并账号，也不能强迫所有人重新注册。旧 home 节点信息成为来源/恢复路由，和当前在线控制入口、游戏节点分开存储。

已有浏览器持钥与客户端签名模型优先保留；新中心通过公开协议验证证明，不索要用户明文密码。既有身份密文迁移/持久复制遵循用户已签署的复制授权；需要扩大范围时由用户明确授权。M1 前确定旧记录签名的验证兼容方式及授权来源，不能把导入 JSON 当作授权验证。

运行授权按用户、设备、用途、audience、期限和 revocation_epoch 绑定；短期运行授权与长期节点入网凭证是不同对象。普通节点只能验证分配给它的短期玩家票据，无法自行为任意玩家签票。

## 在线与多设备

会话键为 account_id/device_id/session_id，附服务端生成的 epoch 和单调序号。先鉴权再接收心跳，旧 epoch 或倒退序号不刷新租期，迟到的断开回调不得影响新的连接。不同设备独立存活；账号在线为至少一个设备会话有效。

初始建议：玩家心跳 10 秒、租期 30 秒；节点心跳 5 秒、租期 20 秒，均加入抖动并按测量调整。租期依据服务端接收时间及可比较的存储时钟，客户端时间只作诊断。失联为 unknown，明确退出且无其他有效设备时为 offline；playing/idle 是独立维度，不能把“在大厅”当作不在线。

控制实例重启后从共享租期或重新注册恢复，不从昨天的磁盘快照恢复“在线”。短期缓存丢失可暂时显示 unknown，不能伪造全网离线，也不能续活已撤销设备。

## 好友、邀请与跨节点消息

关系变更、房间邀请、请求加入、接受、拒绝、撤销均为可追踪事件。事件绑定 actor/target、device、event_id、body_digest、房间 ID/epoch、授权版本及有效期。写入数据库的事件与发送 Outbox 在同一事务；唯一键保证同一事件重复请求只产生一次业务效果，同 ID 不同内容直接拒绝。

三个回执分开：accepted 是持久接受，delivered 是收件设备确认，seen 是用户已读；不能用一次节点 RPC 回复代替对方已看到。WSS 即时推送，断线后按游标取回未过期事件。采用至少一次投递和幂等消费；超时指数退避并抖动，队列按账号/设备/节点限额，不无限积压。

关系记录长期保存；房间邀请建议 300 秒、加入申请建议 120 秒，过期仍保留必要审计而不再可执行。房间关闭或 epoch 改变后旧邀请失效。读取邀请码/加入票据前，由当前房间所有者与中心授权共同校验，不能仅凭“好友在线”或候选节点地址进入游戏。

节点只订阅本机房间及获授权玩家的事件，不接收全量社交快照。聊天与游戏载荷继续使用现有房间通道，控制服务不在本轮接管游戏内聊天正文。

## 存储边界与接口族

| 持久对象 | 权威与约束 |
| --- | --- |
| enrollment_credentials / nodes / node_certificates | 入网、证书、撤销与池归属；密钥私密，长期凭证不落明文 |
| identities / devices / grants | 身份、公钥、设备撤销和用户授权；密文权限保持原约定 |
| friend_edges / social_events / outbox / delivery_receipts | 原子提交与幂等唯一键；按收件账号/事件游标索引 |
| room_owners / allocations / reservations | 房间唯一归属、epoch、容量预留与提交，见 03 |
| leases / health_cache | 在线与健康是可恢复短期状态，缓存丢失不覆盖长期记录 |

拟定接口族：`enrollment.*`、`node.channel`、`identity.*`、`presence.*`、`social.*`、`placement.*`、`room.locate`、`admin.*`。这不是已发布方法名清单。所有会改状态的请求要求幂等键；管理接口与玩家/节点接口的认证、审计和速率预算分离。重试错误区分 temporary、capacity、revoked、expired、incompatible、invalid，不因业务拒绝切换入口绕过策略。
