# 原生账号与迁移

本篇下文保留账号迁移当时的发布摘要；2026-11-11 后续控制程序已增量更新为大厅目录修正版，当前路径与验证见 [13](13-大厅房间目录修正.md)，账号资产与签发配置沿用。

2026-11-11：C++ 浏览器身份入口已部署上海 `node.bugg.icu`，与原有控制协议由同一个原生进程提供。已迁移 17 个账号、1 个设备记录和 14 个邮箱关联，旧 Python 账号服务已停止并禁用。节点运行控制仍待迁移，不能据此宣称全系运行依赖已完成原生化。

## 运行与唯一所有者

`Service::browser/browser_api` 使用既有 Beast TLS 会话、有界工作池、PostgreSQL 事务和 OpenSSL。网页及 WebCrypto 继续复用节点项目的唯一账号前端，此仓库不复制 Vue。注册/登录、邮箱绑定与选择、设备批准、轮询、刷新、撤销写入 `browser_*` 表；设备控制权限继续调用原有 `admin` 域操作，调度和游戏数据不进入账号模块。

`State::submit` 统一两类 HTTP 业务的排队、线程连接、异常与完成回调；同一 worker 的数据库连接不重复建立。`Database::lock` 统一事务 advisory 锁。SSH 公钥/签名封装归 `browser_transport`，P-256、Ed25519、摘要和委托校验复用现有 `crypto`，SMTP/TLS 由 libcurl 提供。没有手写密码算法。

密钥、audience 和 SMTP 设置只在启动时读取，变更后重启生效。会话令牌只以摘要入库，Cookie 使用 Secure/HttpOnly/SameSite=Strict，写操作校验 Origin 和 CSRF。一次性挑战先独立提交消耗，再验证业务；错误签名或验证码不能通过事务回滚重用。设备刷新与撤销锁定同一设备行。待批准请求、活跃会话、发信和响应有容量/超时限制，过期临时记录由维护任务分批清理。

`browser` 为可选配置对象，不启用时保留既有控制协议部署方式：

```json
{
  "origin": "https://node.example.com",
  "assets": "/opt/control/account-assets",
  "issuer_key": "/etc/control/identity/issuer.pem",
  "issuer_public": "ssh-ed25519 <原账号签发公钥>",
  "audience_key_file": "/etc/control/identity/audience",
  "smtp_file": "/etc/control/identity/smtp.json",
  "registration_open": false,
  "trust_loopback_proxy": false
}
```

只有明确使用本机可信 Nginx 时才启用 `trust_loopback_proxy`，此时仅来自回环的连接可提供单一合法 `X-Real-IP`。Nginx 必须覆盖而非透传此头。SMTP 沿用 host/port/username/password/required；465 默认隐式 TLS，587 默认 STARTTLS，其他私有端口可显式设置 `implicit_tls`。始终校验证书与主机名，私有 CA 使用 `ca_file`，没有关闭 TLS 校验的选项。

## 保留数据的迁移

1. 在开发机完成原生构建和验证，确认目标依赖兼容；共享 4 GiB 服务器不编译。
2. 停止旧身份进程并保存私有回退材料，保留原账号库、主机密钥、audience、SMTP、禁用策略及控制数据库。
3. 一次性运维工具 `scripts/export_identity.py` 读取实际账号库 accounts-replica.json、同目录 launcher-devices.json/accounts-email.json，输出权限受限且禁止覆盖的 snapshot.json、原签发私钥 PEM 与公钥。accounts-shared.json 是旧共享策略中的 ID 清单，不是账号记录。工具不进入产品运行包，通过 `--blocked` 传入禁用账号 ID。
4. 执行 `buggcraft-control --config FILE --import-browser PRIVATE_SNAPSHOT`。原生导入重新验证账号证书、状态和设备签名，支持旧 revision 和过期/撤销设备；事务整体提交，目标身份表非空则拒绝覆盖。既有控制账号、好友、房间和节点表保留。
5. 迁移原有 audience 原文及 SMTP 设置，核对记录数、公钥、邮箱关联和禁用状态后切换代理。短期浏览器会话和未完成挑战不迁移，用户重新网页登录；已授权设备保留原 ID 和签名，刷新仍检查撤销。
6. 检查公开域名的登录失败重试、设备批准/刷新/撤销和启动器控制授权。失败时恢复代理与旧进程；迁移后新账号写入 PostgreSQL，不能未经数据回迁长期回退旧 JSON 服务。

禁止通过删除真人账号、重建签发密钥、忽略撤销或放宽认证完成迁移。SMTP 密码、账号密文、会话和私钥不得进入报告或截图。

## 验证边界

2026-11-11 网页风景资源：浏览器静态入口只额外允许构建产物 `/vue-bugg-landscape-{hash}.webp`，按 `image/webp` 返回；继续使用固定 assets 根、严格文件名白名单及 256 KiB 单文件限制。不能扩成任意图片或任意文件下载接口。账号网页资产图打包器随 CSS 引用收集该图片；发布时须先更新原生静态路由，再更新网页资源。

`tests/browser_identity.py` 使用独立 PostgreSQL、真实 TLS HTTP 和校验证书的 SMTPS 夹具，覆盖既有账号 revision、设备历史、拒绝覆盖导入、挑战一次性、CSRF/Origin、邮箱验证码和刷新/撤销并发。它验证协议，不能代替浏览器实际解密、生产数据导入或公网游戏验收；真实 WebCrypto 页面流程另存本地截图。

Linux x86_64 Release/LTO 构建通过单元测试、20 项控制集成及 10 项原生账号集成。Windows Edge 实际 WebCrypto 页面通过注册、错误密码重试、设备批准/轮询/刷新/撤销、邮箱绑定、验证码找回及使用新的 6 位密码重新登录；使用独立 SMTPS 夹具，不向玩家发送测试邮件。

上海实际运行的 ELF SHA-256 为 `7ca286892c6753bb60914628ff7330bdb204a5193af4ece2009bd8a0613a6cd7`，版本目录 `20261111-005056-native-identity`。增量更新前保存控制数据库，保留签发公钥、audience、SMTP、17 个账号、14 个邮箱关联和原设备记录。私有 simdjson 运行库、许可与账号前端对应源码随包保存，运行时无需 Python。公开域名的新资源、登录失败重试、找回页面刷新与密码策略均已复验。

SMTP 沿用已有官方发件邮箱，严格 TLS 与 AUTH 已验证；通过生产 C++ 邮箱接口向该发件邮箱自身发送验证码，SMTP 服务接受成功。未检查收件箱，不据此声称最终收件成功；未使用真人密码或新增生产测试账号。Windows/macOS 服务运行及完整公网游戏链路仍有验收缺口。构建/一次性运维工具可用 Python，尚在迁移的节点仍有 Python 运行依赖。

## 密码找回与注册策略

`/api/account/policy` 为前端注册与重设共用的策略入口：新密码 6–256 个字符，禁用常见弱密码、与用户名相同的密码；系统和管理身份用户名保留。旧账号登录不套用新注册长度限制。浏览器校验后发送瞬时摘要与长度，服务端重复核对禁用摘要但不持久化；加密保险箱不能让服务端证明客户端真的使用了申报密码，非官方客户端仍须遵守同一规则。

忘记密码从 `/forgot-password` 验证绑定邮箱。邮箱票据与后续 recovery-grant 分别一次性、10 分钟有效；先独立事务消耗，失败不能重放。重设在浏览器生成新身份密钥与新密码加密记录，服务端要求正确账号归属、旧 revision+1、签名及本地签发者，再重新签发同一账号。旧网页会话、启动器设备及在线授权失效，账号 ID、邮箱和好友不变。不提供恢复文件或网页备份功能。

## 好友历史与设备展示

离线 `--import-social PRIVATE_SNAPSHOT` 对历史证书、委托及事件逐项验签，接受事件发生时有效而当前已到期的历史委托；只导入 request/accept/remove，不复活过期游戏邀请。整个快照在一个事务中提交，重复导入幂等，已有原生关系优先。上海和北京旧数据合并去重后共有 16 条有效事件，恢复 8 对已接受好友关系。账号页不显示长 ID，启动器仍经 social/state 使用稳定身份与邀请协议。

设备页分别展示启动器设备与网页登录会话，含系统、浏览器、最近使用和当前会话标记。识别来自客户端信息，未知时如实显示，不把 UA 当作可信设备身份证明；撤销只能作用于当前账号的设备或会话。
